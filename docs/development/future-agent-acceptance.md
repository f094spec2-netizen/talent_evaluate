# 後續 Agent 能力契約與案例規格

此文件與 `app/acceptance/contracts.py` 是實作前契約，不是通過證明。每個 Agent 實作前先建立證據輸入、預期欄位、來源定位、語義 rubric、必要升級、來源分組，交管理者核准；再接共同介面。未實作 Agent 的執行要求會被拒絕。

| Agent | 最小案例輸入 | 預期結果 | 阻擋放行錯誤 |
|---|---|---|---|
| 身份歸檔 | E01 的兩個核准別名；兩公司同名員工；暫代起訖日 | 別名歸 E01；同名不同 ID 保留；按成果發生日套用指派 | 錯人、跨公司誤合併、接任前成果歸接任者 |
| 項目去重 | 同項目跨週改名；上月已驗收交付；相似名稱但不同需求 | 保留延續，只計有證據的新交付增量，不同項目不合併 | 重複計功、錯誤合併、丟失版本 |
| 貢獻核驗 | 責任人、實作紀錄、協作評語、驗收／缺件 | 分列主責、實作、協作與各自來源；缺驗收標未核驗 | 團隊產出全給效能官、評語當事實、无證據結論 |
| 能力邊界 | 單次、受指導、多次跨期獨立交付三組記錄 | 分列單次觀察、協助條件、穩定獨立能力候選 | 單次判穩定、忽略協助、擴張能力範圍 |
| 潛力信號 | 多次工具學習起點、掌握里程碑、遷移事件；缺里程碑負例 | 有限趨勢與不確定性；缺資料保留未知 | 一次判高潛、能力驗證當未來保證、編造學習速度 |
| 獨立審核 | 上游結論、獨立來源，植入錯人、矛盾數字、漏規則 | 找到預植問題並引正確來源，不受上游自評影響 | 原樣同意、漏必要升級、不存在的證據 |
| 報告生成 | 已核准帳本、中心推動／業務交付標籤、風險／P0 | 3–5 重點；分開中心貢獻與業務成果，保留未確認資訊及 P0 | 編造數字、混合歸功、把未知寫成完成 |

精確欄位程式比對；敘事忠實性、能力範圍須按已核准 rubric 人工裁定。人工裁定須有版本與理由，不可覆蓋關鍵錯誤。新入職預設、排除名單等人才規則須獨立版本化，不將舊人工評語當作已證實事實。

完整總管還需依賴 DAG、恢復點、例外升級、人員／項目版本衝突與三次模型驗收門禁案例。目前的 12 個總管案例只覆蓋收件與佇列切片。
