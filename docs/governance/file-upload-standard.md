# 文件上传规范

本文件定义目标规范。第一阶段支持范围和状态映射见[实现说明](../development/intake-mvp.md)：目前尚不解析旧版 XLS、PDF 或图片；期间／身份异常需修正文件后重新上传，一键确认界面将在后续实现。

## 1. 必填元数据

每次上传必须能够确定：

- 公司／团队；
- 责任效能官；
- 文档类型；
- 业务期间；
- 版本号；
- 上传人与上传时间；
- 来源系统或形成方式。

Telegram 机器人可自动识别后让上传者一键确认，避免重复填写。

## 2. 文件命名

```text
公司代号_责任人代号_周报_2026-W35_2026-08-24_2026-08-30_v01.html
公司代号_责任人代号_月报_2026-08_v01.docx
公司代号_责任人代号_项目人员确认表_2026-08_v02.xlsx
```

文件名中的日期与周次必须分别计算并核对。文件名只有日期时，系统应推导周次；只有周次时，应推导日期区间。两者冲突时进入黄色确认，不可静默归档。

## 3. 格式优先级

| 类别 | 格式 | 处理规则 |
|---|---|---|
| 推荐 | `.xlsx`、`.csv`、`.json`、`.html` | 优先解析 |
| 过渡 | `.xlsm`、`.xls`、`.docx`、`.pdf` | 可接收，但宏永不执行 |
| 补充证据 | 图片 | 只作为佐证，不作为唯一结构化来源 |
| 拒绝／隔离 | 可执行文件、压缩包、加密或损坏文件 | 不进入自动流程 |

试行阶段建议单文件上限 20 MB，一个文件只包含一个公司、一个文档类型和一个业务期间。

## 4. 周度资料最小字段

- 公司、项目名称／项目 ID；
- 人员、角色、负责事项；
- 任务状态、开始及结束日期；
- 交付结果与验收状态；
- 证据链接或来源定位；
- 最后更新时间。

不要求效能官填写人才等级、潜力、能力分数、项目去重判断或证据充分度。这些由系统生成候选，再由人确认例外。

## 5. 接收状态

- `accepted`：格式与元数据完整，进入处理；
- `accepted_with_warning`：可处理但有非阻断问题；
- `awaiting_confirmation`：日期、周次、身份或版本需确认；
- `rejected_or_quarantined`：加密、损坏、类型不允许或有安全风险。

## 6. 版本与重复

- 上传后计算 SHA-256；同一哈希不重复入库；
- 新版本保留旧文件与差异，不覆盖；
- 上传两个版本只计算一次“已提交”，但以最新已确认版本作为处理输入；
- 解析失败不等于未提交，应区分“已收件”和“可处理”。
