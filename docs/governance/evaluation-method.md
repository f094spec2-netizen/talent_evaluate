# 人才评估方法与治理边界

## 1. 方法定位

本系统用于建立人才评估的事实底稿、能力边界变化与潜力趋势信号，不宣称从项目记录自动得到“绝对客观”的人才等级。项目资料只能降低信息遗漏与主观偏差，不能消除管理判断。

## 2. 四项判断原则

1. 不额外增加工作量：优先复用项目软件、交付记录、验收结果及自然形成的周度记录。
2. 已发生事实仅代表员工已经验证的可承担范围，不代表未来一定能承担更高难度工作。
3. 潜力可以从学习新工具到独立掌握的速度、支持依赖下降及跨场景迁移中观察，但只能作为概率信号。
4. 员工完成超越原能力边界的交付，证明其能力边界已经扩大；这仍不是对未来潜力的直接判定。

## 3. 能力证据强度

| 层级 | 定义 | 可支持的结论 |
|---|---|---|
| A | 项目系统、代码／发布、验收或业务系统的可核验记录 | 高可信工作与结果事实 |
| B | 结构化确认表，责任人与期间明确 | 中高可信贡献事实 |
| C | 周报、月报或主管说明，可定位但缺少系统验收 | 待补强的候选事实 |
| D | 自由文字、截图或无法定位来源的描述 | 线索，不单独形成能力结论 |

证据等级代表来源可核验程度，不等同于员工表现高低。

## 4. 能力与潜力分离

### 能力边界

观察任务难度、责任范围、完成质量、支持程度和重复稳定性。单次成功可以形成“已验证一次”的能力记录；在第二个独立场景再次成功后，才提高稳定性判断。

### 潜力信号

至少观察多个周期或多个学习事件：

- 从接触到独立交付所需时间；
- 所需提示、协助和返工是否下降；
- 是否能把方法迁移到不同项目或问题；
- 是否能沉淀工具、模板或方法供他人复用；
- 是否在难度提高后仍维持质量。

样本不足时必须输出“无法判断”或“信号不足”，不能用积极措辞补足证据。

## 5. 禁止直接推导

- 任务数量、工时、消息数量、提交次数不得直接转为人才分数；
- 项目成功不得自动归因于某一成员；
- 报告写得详细不得视为贡献更高；
- 单次加班、救火或高难度交付不得直接等于高潜；
- 新入职默认等级若作为业务规则使用，必须标记为“管理默认值”，不得伪装成系统评估结果。

## 6. 评估节奏

- 每周：新增事实、风险和异常确认；
- 每月：聚合变化，不重复重建事实；
- 事件触发：能力边界新增或增强候选；
- 每季度：管理者进行正式人才校准；
- 规则变更：保留旧版本并可重跑，不覆盖历史判断。
