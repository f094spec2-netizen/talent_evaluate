# 安全、隐私与权限

## 1. 资料分类

| 等级 | 示例 | 处理要求 |
|---|---|---|
| 公开 | 去识别化架构、通用规则、公开代码 | 可进入本公开仓库 |
| 内部 | 流程配置、非个人化统计、项目模板 | 仅限授权环境 |
| 机密 | 员工姓名、工作记录、人才评估、管理意见 | 私有存储、最小权限、审计 |
| 高敏感 | 负面人才结论、处分、身份凭据、密钥 | 加强审批、加密、严格限制导出 |

## 2. GitHub 规则

当前仓库为公开仓库，只允许提交去识别化内容。以下内容禁止进入 Git：

- 原始 Excel、Word、PDF、HTML 周报／月报；
- 员工、效能官、项目客户或内部组织的真实名单；
- 人才等级、潜力判断、敏感管理意见；
- Telegram Bot Token、模型 API Key、数据库连接串；
- Railway、对象存储或其他平台凭据。

若未来需要版本管理真实规则配置或测试样本，应先将仓库改为私有，并继续使用脱敏样本进行自动测试。

## 3. 运行环境权限

- 只有 `tg-api` 暴露公网；worker、PostgreSQL 与 Bucket 走 Railway 私有网络；
- Telegram 依据用户 ID 白名单和角色授权，不依赖用户名；
- 群聊只允许提交状态和一般通知，个人评估仅在授权私聊或管理端显示；
- 生产与测试环境分离，生产项目仅开放给少量管理员；
- 密钥使用 Railway sealed variables，不写入代码、日志或模型提示；
- 所有人工确认、修改、发布和下载均记录审计日志。

## 4. 大模型资料最小化

- 只发送完成任务所需字段；能以内部 ID 代替姓名时，不发送姓名；
- 原始文件先在应用侧解析，再将必要片段送入模型；
- 模型输出不得包含来源中不存在的事实；
- 记录模型供应商、模型版本、提示版本、输入摘要与 trace ID；
- 供应商条款、资料保留政策与地区要求由项目负责人在上线前确认。

## 5. 备份与恢复

- PostgreSQL 使用平台快照／PITR，并定期执行逻辑备份；
- 对象存储保留版本或不可变备份策略；
- 至少保留一份加密的异地备份；
- 定期执行恢复演练，备份成功不等于可恢复；
- 依公司制度定义原始文件、事实记录、人才评估与审计日志的保留期限。
